# Package 25b — entrant-tier every-string ledger, verdicts

Scope: every ledger key in `docs/audits/v3-consolidated/ledger/LEDGER.md` whose `file` (per
`scan.json`) starts with `apps/entrant/` and whose current verdict is `unreviewed`. This document
does not edit `LEDGER.md`; it is the entrant-tier (package 25b) companion package 25's report asked
for from packages 21/24, generalized to the whole remaining entrant unreviewed set per this
package's brief. Console-tier (`apps/`) rows are out of scope — a separate agent covers OC01–OC33
and the operator shared-chrome buckets.

**Baseline:** HEAD `bd2d6e58`. Package 24 (`apps/entrant/app/routes/{partner,myEntries,receipt,
enter}.tsx` and the `my-entries.js`/`partner-accepted.js`/`entry-wizard.js` browser twins) is
editing concurrently; those files were reviewed as they read at this HEAD and are marked
**re-check after 24** in their evidence column rather than left unreviewed, per this package's
brief.

## Method

1. Read `docs/audits/v3-consolidated/plan.md` §4 (the text-must-behave-like-website-text rules
   table and the ten ledger columns) and §7 (surface → package map), `docs/reference/contracts/
   state-and-formatting.md` §§2, 3, 6, 7, 9 (match/schedule state vocabulary, missing-data
   fallbacks, identity/side formatting, time contexts, public-visibility projection) and
   `docs/reference/contracts/match-card.md` §3 (the shared MatchCard primitives — `StateWord`,
   `SideBlock`, the "versus"/"and" accessible phrase, the winner mark), and
   `docs/audits/v3-consolidated/reports/25-string-ledger.md` (package 25's method, exclusions and
   the one pre-existing `flagged` row, `schedule.tsx:641` "Schedule / Live" — out of this package's
   row count because it already carries a verdict, `flagged`, not `unreviewed`; still an open
   assignment problem, noted below).
2. Loaded `docs/audits/v3-consolidated/ledger/scan.json` (`{key, file, line, text, kind}` entries)
   and `docs/audits/v3-consolidated/ledger/LEDGER.md`, and computed the exact set of entrant-tier
   `unreviewed` keys by joining scan entries (`file` starting `apps/entrant/`) against LEDGER.md's
   current verdict for that `file:line`, rather than trusting the surface-heading grouping alone —
   `LEDGER.md`'s "Unassigned (scan heuristic could not attribute a surface)" block runs under the
   `PE-CHROME-ASSET` `##` heading with no `##` of its own and mixes in nineteen **console**-file
   rows (`apps/console/src/lib/stateWords.ts`, `apps/console/src/pages/TournamentPage.tsx`); those
   are excluded from this ledger by file-prefix, not by heading, and are the console agent's scope.
3. For every one of the resulting 255 keys, read the string in its file context (`sed -n` batches
   per file/component) and recorded a verdict against plan §4's rules table and the two contracts:
   slash-assembled compounds, relative-only dates, counts without nouns, "Live" used as a match
   state, placeholders asserting an unverified time/court/date, success wording inferring an
   unverified outcome, and hover/`title`-only affordances were checked on every row.
4. A handful of strings the scan captured as separate JSX-text nodes are one sentence split by the
   scan's own documented heuristic gap (an embedded `{expression}` breaks a JSX text run into two
   entries) — these keep their scan-derived row (deleting rows the tool emitted is out of this
   package's remit) but the evidence column reassembles and cites the whole sentence.
5. Ten rows are `apps/entrant/app/lib/ui.ts` Tailwind class-string constants (its own docstring:
   "Shared class-string vocabulary for the entrant tier ... its 'primitives' are class constants,
   not interactive components") that the scan's `label-map:ui.ts` extractor captured as if they
   were visible label text. They are never rendered as text — they are `className` values — so
   they get **cut-from-ledger** rather than a content verdict.

  "Live"), matching the contract's explicit "a section may be headed 'Live now'" allowance — neither
  is a MatchCard `StateWord`. See their evidence rows below. The one confirmed violation,
  `schedule.tsx:641` "Schedule / Live" as an actual page `<h1>`, was already caught by package 25 and
  carries the ledger verdict `flagged`, not `unreviewed` — it is therefore **not** one of the 255
  rows here (package 25's own row-count rule excludes it), but it remains unassigned to an owning
  package; see "Open item" below.
- *Slash-assembled compounds* — grepped the same `slash-pair-names` shape package 25 used; no new
  hit in the 255 rows beyond the one above.
- *Relative-only dates / counts without nouns* — none found; `dayMatchCountLabel`/`entryCountLabel`-
  style helpers already carry nouns everywhere this package's rows touch.
- *Placeholders asserting an unverified time/court/date* — none found in these 255 rows;
  `MatchCard.tsx`'s placeholder footer (`'Date to be confirmed'`/`'Time not assigned'`/`'Court
  information unavailable'`) was package 04/11's row, already `cut`/`change` in `LEDGER.md`, not
  `unreviewed`.
- *Success wording inferring an unverified outcome* — checked `receipt.js`'s "Entry received" and
  `partner-accepted.js`'s "Entry accepted": both render only after a successful account-scoped
  fetch confirms the record exists (`loadReceipt`/`loadPartnerAccepted`), not optimistically, so
  they are verified-outcome statements, not inferred ones.
- *Hover/`title`-only affordances* — none of the 255 rows introduce a `title`-only route to content
  (`MatchCard.tsx:170` "Match source" is a real `<a>`, not a tooltip).
