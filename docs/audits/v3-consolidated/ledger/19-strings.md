## Notes / debt

- **Result counts excluded from `BackupEntryDTO` (ruling R2's "state precisely why not"):** recorded match results (scores) live in the `match_states` table, which is separate from `tournaments.data`/the stored backup `snapshot` and is never part of what a backup captures. A past backup therefore has no result count to report without re-deriving live state against historical data that doesn't exist for old snapshots. `matchCount` (scheduled matches) and `entryCount` (roster size) are the two counts the snapshot can cheaply and honestly carry; this is logged in `docs/reference/debt-log.md` as a candidate follow-up if backups are ever extended to snapshot `match_states` too.
- **`lib/formatDateTime.ts` (contract §7.3 authority) does not exist yet** — it is package 07's deliverable, not shipped as of this branch. `SyncBackupsTab.tsx`'s new timestamp formatters implement the same rules (tournament timezone, explicit zone abbreviation, seconds only to break a same-minute tie) locally, with a code comment flagging the redirect once that authority lands, per contract §7.4's assignment of `SyncBackupsTab.tsx` timestamp code to package 19.
