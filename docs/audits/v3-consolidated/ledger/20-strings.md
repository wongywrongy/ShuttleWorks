## Notes / debt

- **Retention is a count cap, not a time-based prune.** `document["activity"]` has always been truncated to the last N entries (`activity[-200:]`) on every write — there is no scheduled job that deletes activity by age. Ruling R4's copy therefore says "Kept for the most recent 200 changes," sourced live from `ActivityFeed.retentionLimit` (backed by `ACTIVITY_MAX_ENTRIES`), not a fixed-days claim the product does not make.
- **Old-to-new diffs only exist going forward.** `_diff_fields` compares the setup document's previously *stored* section data (which is empty until a section is first PATCHed) against the newly validated payload — a workspace's very first edit to a section therefore shows `old: null` for every changed field (there was nothing stored yet to diff against), which is the honest answer, not a placeholder. A second edit to the same section shows a real prior value. Covered by `tests/backend/test_tournament_setup.py::test_setup_patch_records_actor_section_and_field_diff`.
- **`lib/formatDateTime.ts` now exists** (this package's deliverable, closing V3-19-2 from package 19's debt log). `apps/console/src/modules/settings/SyncBackupsTab.tsx`'s four local timestamp helpers (`minuteKey`, `dayLabel`, `fmtTime`, `fmtTimestamp`) now import from the new authority instead of defining their own copies — behavior unchanged, verified by the existing `SyncBackupsTab.test.tsx` suite passing unmodified.
- **Diagnostics (`payloadHash`) are new and therefore absent on rows written before this package.** Those rows render `payloadHash: 'not recorded'` in the details disclosure rather than a fabricated hash.
