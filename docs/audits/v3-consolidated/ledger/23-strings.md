# Ledger — package 23 (account, confirmation and reset journeys)

Columns per plan §4: string key/file:line · surface · state · current text · verdict · final text · factual prerequisite · finding IDs · evidence.

Builds on package 05's ledger (`docs/audits/v3-consolidated/ledger/05-strings.md`, section A4), which
established the mail-outcome mechanism (`_mail`/`_send_verification` return a real `bool`) and the
enumeration-safe reset request (uniform 202/303, TTL carried on every redirect regardless of whether
the address exists). Nothing here reopens either invariant — every change below keeps both branches of
signup/login/reset-request byte-identical for a fresh vs. a registered address, which is asserted by
the existing `tests/signup.test.ts` / `tests/login.test.ts` byte-comparison suites.
