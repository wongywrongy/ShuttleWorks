## B3 — Considered and NOT changed

| item | why no change |
|---|---|
| `SetupProduct.tsx` "entries" section payment/waitlist/approval controls | Already `Toggle` (role="switch", aria-checked) for a genuinely binary, immediate-per-save-cycle setting — matches ruling R3. Only the shared `Toggle`'s hit-area size changed (B2 above), not the control choice. |
| `AppearanceSettings.tsx` Density (`Seg`, comfortable/compact) | Genuinely binary and applies immediately (no Save), but kept as a labelled two-option segmented control rather than converted to a bare switch: it names the specific state ("Comfortable"/"Compact") rather than an unlabelled on/off, and no audit finding pins it as a "selected Off reads as enabled" defect. R3 requires converting where a control is *mis-styled* as a color cue for a binary state, not that every binary-immediate setting must use the `Switch` widget. |
| `SetupProduct.tsx` "Partner rules" field (V3-OC11.1) | Routed to package 18 (`packages: ["13"]` in findings.json — not package 08's cross-cutting routing X4/X12), not touched here. |
| `GlobalSettingsPage.tsx` ProfilePage copy reorder ("Sign in to edit your profile" above the fields, made primary) | V3-OC04.1's fuller redesign is explicitly package 18's scope ("Finish account, team, tools and settings — locked forms show a useful action", depends on 08). This pass only removes the disabled-with-no-reason Save (B1 above), which 18 builds on. |
| `SharingTab.tsx` invite-mode radio buttons (`<label><input type="radio">…</label>`) | Already real `<label>`-wrapped, already keyboard/touch accessible. Hit-area height is borderline (~20px, text-line-height dependent) but no finding or test flags it, and enlarging every radio row risked destabilizing an already-dense settings surface out of proportion to this package's scope; logged as debt below rather than guessed at. |
